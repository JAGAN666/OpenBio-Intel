Abstract

Commercial biopharma intelligence platforms are closed, priced per seat, and opaque about how their answers are produced. OpenBio-Intel is an open alternative. An agent searches seven hybrid-indexed collections holding more than 630,000 records plus a drug knowledge graph, extracts structured findings from each matching trial in parallel, and writes an answer in which every row and claim cites its source. It runs on your own infrastructure, so your questions never leave it.

1Why build this in the open

Trial registries, FDA databases, SEC filings and press releases are public. Most of what commercial platforms sell is the layer on top: extraction, entity resolution and monitoring. That layer decides which trials count, which drug names match and which numbers end up in a slide deck, and today it is a black box.

OpenBio-Intel puts that layer in a repository you can read. When a number looks wrong you can trace exactly how it was produced. When you need a new source, you add it. And because it is self-hosted, the questions your team asks, which are competitive intelligence in their own right, stay inside your network.

The answer synthesis is not allowed to supply a drug’s mechanism from the model’s own memory. If no retrieved record describes it, the row says so.

2Three instruments, one retrieval layer

Each instrument answers a different shape of question. They share the same sources, search and citation rules.

2.1Smart Table

Ask a question and get a cited briefing plus a comparison grid. The agent fans out one extraction worker per matching trial, shows live progress, and attaches a registry link to every row, with PubMed, SEC or news citations added only when that evidence was actually used. Export the grid to Excel or PowerPoint without re-running anything.

Interrupted queries resume from their last completed step. Measured: 33 seconds to resume against about 150 seconds to restart.

2.2Indication Landscape

Name a therapeutic area and get a competitive matrix: mechanism or target down the side, development phase across the top. Every cell is grounded in retrieved trials, FDA records and literature, and opens to the records behind it.

2.3Catalyst Tracker

A timeline of upcoming events that move markets: Phase 3 primary completions, PDUFA action dates and advisory committee meetings. PDUFA dates are not published by the FDA, so like every commercial calendar they are mined from company filings and press releases. Here, each event shows the disclosure it came from.

2.4Watchlists

Watch a drug, company, trial or topic. One check compares ClinicalTrials.gov updates and new FDA rejection letters against your last run and shows only what changed.

FDA Complete Response Letters, the full-text rejection letters published since mid-2025, are indexed and searchable: 459 letters split into 3,410 passages.

3Methods

3.1Sources

Everything comes from public primary sources. Some are indexed ahead of time, and some are queried live when you ask.

FAERS shows association, not causation. The tool says so in every result.

3.2From question to cited answer

A classifier first checks that the question is in scope. A tool-calling agent then decides which sources apply. Drug names are resolved through a Neo4j graph built from RxNorm, so “Keytruda”, “pembrolizumab” and “MK-3475” match the same trials by exact traversal rather than by similarity. Text search fuses keyword and embedding results, and a cross-encoder reranks them. One extraction worker runs per matching record, and a final step writes the answer with its citations.

4Results

Retrieval quality is measured, not asserted. The golden set, harness and baseline are committed to the repository, and CI runs the comparison as a regression gate. Ground truth comes from exact filters on the stored records, so the retriever being tested plays no part in defining what counts as relevant.

Search using embeddings alone found nothing relevant for 13 of 50 realistic analyst queries, mostly ones naming exact development codes such as ABX464 or BBO-10203 that embeddings blur. Adding keyword search and reranking cut that to 7 and lifted mean recall by more than a third.

5Discussion

Mature platforms such as Cortellis and AlphaSense have decades of hand-curated records, consensus forecasts, investigator databases and support teams behind them. OpenBio-Intel does not try to fake any of that. It is the better choice when you need intelligence you can audit, host yourself and extend.

5.1Known limitations

  • Purple Book coverage is partial, because the FDA publishes no complete extract. Results say so.
  • ASCO, ESMO and AACR abstracts are not ingested; their licenses forbid redistribution. Readouts are covered through company press releases and 8-Ks.
  • PDUFA dates are extracted from company disclosures, not official FDA data. Each one carries its source.
  • The quickstart seed is 100 records, enough to try the interface. A research-grade corpus takes hours to ingest and has real embedding cost.

6Availability

6.1Run it locally

You need Docker, an OpenAI key for embeddings and an Anthropic key for the agent. The script starts Qdrant, Neo4j, the API and the web app, then loads a small seed so you can try a query straight away at localhost:3000.

git clone https://github.com/JAGAN666/OpenBio-Intel.git
cd OpenBio-Intel
./quickstart.sh

6.2Use it from Claude

The bundled MCP server exposes every tool and the full Smart Table pipeline to Claude Desktop, Claude Code or any MCP client, running against your own data.

{
  "mcpServers": {
    "openbio-intel": {
      "command": "uv",
      "args": ["run", "--project", "/path/to/OpenBio-Intel",
               "python", "mcp_server.py"]
    }
  }
}

6.3Deploy it

The repository includes a reference AWS deployment in Terraform (ECS Fargate, a load balancer and EFS) with a GitHub Actions pipeline. It is optional; Docker Compose on a single machine works too.

The model provider is a single setting: Anthropic, Kimi or NVIDIA-hosted models handle orchestration.
